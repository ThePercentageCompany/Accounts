# Cash customer option for invoices & quotations

## Context
Walk-in sales have no saved customer account, but the editors force choosing a customer. Request: a **"Cash customer"** option in the invoice and quotation editors; when selected, the customer picker is replaced by an **optional** name field, and the document shows **"Cash Customer - xyz"** (or just "Cash Customer" when no name is given). Payments against cash invoices and generated PDFs/HTML must keep working.

## Design
- New optional payload field `cashCustomerName` (text, ≤200 chars, trimmed) on Invoices/Quotations. A cash sale is simply an invoice/quotation with an **empty `customerId`** — the field is only allowed then. Display name is computed at render time: empty → `Cash Customer`, else `Cash Customer - <name>`.
- No database migration needed: payloads flow through `business_records` to the client as-is (`validateRelations` already skips empty `customerId` strings, and `validateBusinessValues` accepts text fields). `company-schema.js` FIELDS lists get the new column so CSV/workspace exports include it.

## Server (`supabase/functions/_shared/domain/`)
1. **`invoice-policy.js`** — draft create/update validation (L124): accept `customerId: ''` when `cashCustomerName` is a valid optional string ≤200; reject `cashCustomerName` when a real customer is chosen; store trimmed. Issue validation (L53): `typeof old.customerId === 'string'` (allow empty) so cash invoices can be issued.
2. **`quotation-policy.js`** — same create-validation change (L73); quotation→invoice `convert` copies `cashCustomerName` to the created draft invoice.
3. **`invoice-return.js`** — credit note copies `cashCustomerName` from the invoice so credit-note PDFs show the cash name.
4. **`receipt-policy.js`** — `receiptInput` (L18) also accepts `customerId: ''`; in `receiptChanges` skip the customer-lookup requirement for cash receipts (invoice↔receipt `''` match still enforced) and copy the invoice's `cashCustomerName` onto the stored receipt.
5. **`company-schema.js`** — add `cashCustomerName` to Invoices, Quotations, Receipts, CreditNotes field lists.
6. **`document-design.js`** (`snapshotHtml` L69-72) — when `customerId` is empty, render a synthetic customer `{name: 'Cash Customer' | 'Cash Customer - <name>'}` and relax the `requireThat(company && customer)` guard so the server HTML design works for cash documents (covers Receipts and CreditNotes too, which carry the copied name).

## Client (`lib/features/documents/`)
7. **`document_editor.dart`** (shared by `InvoiceEditor` and `QuotationEditor`) —
   - state: `cashCustomer` (initialised true for records with empty `customerId`) + `cashName` controller (init from record, disposed).
   - "Customer & dates" section: a `SwitchListTile` "Cash customer" above the picker; when ON, an optional "Customer name (optional)" text field (max 200) replaces the customer dropdown.
   - `_save`/`header`: send `customerId: ''` + `cashCustomerName` when cash is on; `customerId` + empty name otherwise (existing validator still requires a customer when the switch is off).
   - HTML preview passes the synthetic cash customer map so live preview matches the final PDF.
8. **`shared_record_pdf.dart`** — party resolution: `find(Customers, customerId)` currently throws for empty ids; when `customerId` is empty, build the cash party map instead. Applies to Invoices, Quotations, CreditNotes and Receipts paths.
9. **`receipt_editor.dart`** — no change: it already takes `customerId` from the selected invoice (`''` for cash) and the open-invoice dropdown lists cash invoices naturally.
